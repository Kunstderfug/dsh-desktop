Structural reading (src/main/index.ts:504-508, src/main/runtime/harness-runtime.ts:283-312):
`configureAppIdentity()` pins dev userData to `app.getPath('appData') +
'dsh-desktop-dev'` and the harness spawn env overrides any inherited
`DSH_HOME` with `dshHome = userData/harness`. On macOS `appData`/`logs` come
from the real user paths regardless of `$HOME`, so `npm run dev` can only ever
compose the shared dev home — and the boot itself performs shared-home
maintenance ("previous Harness stopped", "cleared … cookie(s)", pnpm shim
rewrite). A scratch DSH_HOME is structurally unreachable for the Electron
shell without editing committed code. The compliant live lane therefore booted
the same harness entry the desktop spawns (`node
node_modules/@deepseek-ai/dsh/lib/bin.js web --patch
build/dsh-desktop.patch.yml …`) with `DSH_HOME` pointing at the scratch copy —
see live-session-catalog-and-execution.json and the report's dev-app section.
